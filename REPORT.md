# Лабораторна робота 8 — система черги поліклініки

## Варіант 14

- Основна сутність: лікар (`doctors`).
- Залежна сутність: талон прийому (`appointment_tickets`).
- Зв'язок: один лікар має багато талонів; поле `doctor_id` є зовнішнім ключем із каскадним видаленням.
- Схема створюється та узгоджується викликом `sync_schema()`. Перевірку зовнішніх ключів вмикає `foreign_keys(true)`.
- Повторний запуск відновлює контрольний набір із п'яти лікарів і п'ятнадцяти талонів.

## SQLite C API і sqlite_orm

| Характеристика | SQLite C API | sqlite_orm |
|---|---|---|
| Кількість коду | Більше: підготовка запиту, прив'язування кожного параметра, перевірка коду виконання та читання кожного стовпця | Менше: `insert`, `get_optional`, `update` і `remove` приймають об'єкти та члени моделі |
| Перетворення даних | Ручне: `sqlite3_bind_*` і `sqlite3_column_*` | Автоматичне на основі відображення `make_column` |
| Керування ресурсами | Потрібно звільняти statement і connection; у прикладі statement керується RAII | Connection та statements обслуговує ORM |
| Обробка помилок | Перевірка кодів SQLite і формування повідомлень | Помилки БД передаються виключеннями |
| Супровід | Імена стовпців і типи повторюються в SQL та C++ | Відображення централізоване у визначенні схеми; CRUD працює з моделями |

Обидва підходи виконують однакові операції додавання лікаря та отримання
за ідентифікатором. Демонстраційні записи для цього порівняння після перевірки
видаляються.

## Реалізовані запити

1. Фільтрація лікарів за спеціальністю.
2. Сортування талонів за часом прийому з обмеженням вибірки п'ятьма рядками.
3. Середня тривалість прийому (`AVG`).
4. `INNER JOIN` лікарів і талонів із вибіркою полів обох сутностей.

## Перевірка транзакції

Логічна операція — реєстрація лікаря разом із першим талоном прийому.
Успішний сценарій додає один запис до кожної таблиці.

У сценарії відкату спочатку додається лікар, після чого створення талона
з неіснуючим `doctor_id` порушує зовнішній ключ. Виняток обробляється, а
кількість лікарів і талонів до та після помилкового сценарію порівнюється.
Програма завершується з помилкою, якщо зміни не було скасовано повністю.

## Збирання

Установіть vcpkg і налаштуйте змінну середовища `VCPKG_ROOT`, потім із
каталогу проєкту виконайте:

```powershell
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE="$env:VCPKG_ROOT\scripts\buildsystems\vcpkg.cmake"
cmake --build build
.\build\Debug\clinic_queue.exe
```

Для генератора, який створює виконуваний файл в іншому каталозі конфігурації,
запустіть `clinic_queue.exe` із відповідного каталогу `build`.
